## 3. 关键决策（合并时请保留这些理由）

1. **只发便携 zip，不做安装包**（默认）
   更新一条命令 45 秒出包，用户解压覆盖即可，`data\` 不丢；安装包/单文件留成开关，需要时再加。
2. **"用户不用装环境"靠 PyInstaller，不靠改源码**
   源码 + bat 的 zip 用户仍要装 Python，所以必须打 exe；安装壳只是 17 秒的额外成本，默认不发。
3. **送进抖动器之前先吸附 6 色**
   PIL 抗锯齿产生的灰边会被 Floyd–Steinberg 扩散成白底彩色麻点；`snap_palette()` 后误差为 0，白底干净。照片区域用 `keep` 保留抖动。
4. **版式：固定槽位只管页眉/页脚，正文"先分配空间再放大"**
   元素尺寸跟着字号线性变、位置写死，是之前所有压字/粘连的根因。现在：行距/块高走 `P()`；重复元素（点阵）尺寸由分到的空间反推；动态锚点向页脚线回收；放不下就降级（降字号 / 少一行 / 整块跳过）。
5. **推送节奏照官方 App 真机日志来**
   MTU 247 → 每块 240B、连接间隔 15ms、窗口 16 块、719 块 6.46s；官方自己 3 次里失败 2 次且都卡在最后 ~15 块 → 我们加了尾包兜底。参数集中在 `sender.py` 顶部，有 `docs/BLE-传输参数.md` 对照。
6. **连接用"地址重建"而不是扫描对象**
   实测按扫描到的 BLEDevice 连接经常 25s 超时（GATT/加密握手卡住），按地址重建 client 往往立刻连上；再配合原地连续重试（第一次常用来热链路，和上游 macOS 的 probe 同一思路）。

## 5. 已知问题 / 下一步建议

1. **卡片电量低时链路会变慢**：实测出现过 5~6 块/秒（正常 64~69）且收不到显影确认。
   建议下一步读 `0x180f` Battery Service 在界面上显示电量，低于阈值时提示"先充电"。
2. **偶发连不上多半是 Windows 配对信息失效**：表现是"能扫到、连不上（TimeoutError）"。
   现在失败提示里已写明"设置→蓝牙移除后重新配对"；可以考虑加一个「修复配对」按钮
   （先 `unpair` 再引导进配对窗口）。
3. **发送参数还能再对**：手机端 HCI snoop 是关的，`docs/BLE-传输参数.md` 末尾写了怎么打开
   （`setprop persist.bluetooth.btsnooplogmode full`，重开蓝牙后复现）。拿到 `btsnoop_hci.log` 可以把
   69 块/秒再往上对到 111 块/秒，并确认尾包 ACK 的真实行为。
4. **macOS 侧本轮完全没验证**：`启动（macOS）.command`、`_send_macos`、Swift 工具链都保持原样。
5. **`release\` 里的 21.9MB zip 不该进仓库**：`.gitignore` 已忽略，发版时只把最新一个挂到 Release。
